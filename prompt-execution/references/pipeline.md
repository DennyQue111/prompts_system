# 阶段细则

## 阶段 0：风格定义

- 输入：剧本文本、用户风格偏好（如 UE5 写实 / 2D anime / 油画风等）、候选图像模型（Flux / Z-Image / GPT 等）。
- 做法：选 2-3 个代表性场景（建议一张场景建立镜头、一张人物镜头、一张复杂构图），用候选风格后缀试生成。不同模型的速度和质量差异在此阶段即可评估。
- 输出：确认的风格后缀文本 + 确认的图像模型。风格一经确认，全项目沿用，不中途更换。
- 确认门：用户看过试生成图后明确确认风格。不确认不进入概念资产阶段。

## 阶段 1-2：概念资产与确认

概念资产的生成方式取决于阶段 0 确定的图像渲染器。Flux 和 GPT 的流程不同，不要混用。

### Flux 渲染器

Flux 的 i2i（flux-kontext）会被多视图 sheet 搞混，因此需要两类角色资产：

- **身份锚图**（生产参考用）：单人正面照，neutral 背景，flux t2i 生成。这是 Flux i2i 关键帧的参考图。
- **角色概念图**（MiniMax 视频参考用）：front/back 双栏 concept sheet，用应用的 Concept Image 工作流或 Flux t2i 生成。这是 MiniMax 视频的角色细节参考。
- 两者用途不同，不要互相替代。身份锚图不用于 MiniMax，概念图不用于 Flux i2i。
- 场景：每个出现 ≥ 2 镜的场景生成一张场景锚图（flux t2i，无人）。
- 道具：需要跨镜头保持身份的道具单独出图。

### GPT 渲染器

GPT 理解多视图概念图的能力更强，流程更简单：

- **角色概念图**：直接用 GPT 生成角色概念图（可含多视图）。该图同时用于关键帧生成和 MiniMax 视频参考，不需要额外生成身份锚图。
- **场景概念图**：直接用 GPT 生成场景图。该图同时用于关键帧生成参考。
- 道具：需要跨镜头保持身份的道具单独出图。

### 通用

- 全部资产路径回填 concepts JSON 的 `reference_images`，保持镜头表系统可追踪。
- 确认门：用户快速过目角色与场景锚图，气质不对在这里改最便宜。

## 阶段 3-4：分镜拆解与确认

- 输入：剧本文本、已确认的风格、已生成的概念图（角色外观 / 场景空间作为分镜参照）。
- 输出：`{CODE}_concepts.json` + `{CODE}_shot_breakdown.json`，遵守 `prompts_structure/script/shot_breakdown` 的 schema 与镜头覆盖规则。
- 此时概念图已存在，分镜可参照角色外观和场景空间精确编写 camera/framing/action，而非凭空想象。
- 确认门：整表给用户看，重点确认镜头数、时长分配、拆镜粒度、正反打与反应镜头的覆盖是否合理。通过前不生成任何关键帧。

## 阶段 5-6：关键帧与质检

关键帧的生成方式同样取决于渲染器。

### Flux 渲染器

- **首选路径**：身份锚图 + 场景锚图 → Flux i2i（flux-kontext），提示词描述镜头的 camera/action/lighting。
- **三段式回退**（首选路径质检不合格时使用，见 `ai-image-video-generator.md` 的 Three-stage keyframe fallback）：
  1. Camera plate：基于场景锚图，按镜头的实际机位/视角/构图生成一张无人场景图（Flux i2i）。
  2. Action plate：基于身份锚图，按镜头的动作/姿态/朝向生成一张中性背景的角色图（Flux i2i）。
  3. Final composite：把 camera plate + action plate 作为两张参考图提交 Flux i2i，合成最终关键帧。
- 不要对同一提示词无限重试。首选路径失败一次后即进入三段式回退。

### GPT 渲染器

- **直接生成**：角色概念图 + 场景概念图 → GPT 直接生成关键帧。GPT 能理解多视图概念图，不需要拆成身份锚图。
- 如果质检不合格，改提示词重试一次；仍不合格标记 blocked。

### 通用质检清单

1. 人物身份是否与锚图一致
2. 构图与机位是否符合镜头 JSON 的 camera 字段
3. 空间关系是否与建立镜头一致
4. 动作起始状态是否适合作为视频首帧
5. 无多余人物、多余实体、被实体化的抽象氛围

不合格先改提示词再重抽，不要同一提示词反复碰运气。

## 阶段 7：回填镜头表

- 关键帧一通过质检，立刻把路径写进镜头表 JSON 对应镜头的 `reference_images`，不要等到整轮结束再统一补。
- 角色/场景/道具锚图同理：生成确认后回填 concepts JSON 的 `reference_images`。
- 路径格式与系统现有约定一致（如 `/static/projects/...`），保证前端画布和镜头表页能直接显示。
- 视频完成后，视频文件路径也追加到对应镜头的记录里（或单独的视频状态表），让 JSON 始终是唯一事实来源。

## 阶段 8-9：视频与复盘

- 单镜视频提示词：镜头 JSON（action/camera/dialogue/continuity/duration）+ 关键帧（构图）+ 锚图（身份）。
- 长镜续接：用上一段的尾帧作为下一段起始帧，并在 `continuity` 标注续接关系。
- MiniMax H3 对白遵循应用集成档案中的“对白只写一次 + 单独时间段”规则；台词准确度对成片至关重要时，仍规划“需后期配音”，不把提示词视为确定性配音控制。
- 回收后核对状态表：确认每镜最终状态，把本轮新发现的问题写进 `lessons-learned.md`。
