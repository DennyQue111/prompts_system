# 制作问题归档

按“症状 → 原因 → 规则”记录。新问题追加到对应分类，不要删除旧条目。来源项目标注在条目末尾。

## Flux / 关键帧

1. **多视图 concept sheet 被当成多人物**
   - 症状：用三视图 character sheet 做关键帧参考，画面里出现两个人。
   - 原因：Flux 会把同一个人的多视图误读为多个角色。
   - 规则：concept sheet 只做设定确认；关键帧与视频参考改用单角色身份锚图。多角色镜头 = 每个角色一张身份锚图 + 一张构图锚图。（WWHD）

2. **抽象氛围被实体化**
   - 症状：“黑暗中的诡秘嬉笑”生成背景里两张女人脸。
   - 原因：Flux 会把抽象描述具象成实际实体。
   - 规则：Flux 提示词只写可见证据；抽象气氛拆成光、雾、声源方向等具体画面元素。（WWHD）

3. **“不可见的危险”被画出来**
   - 症状：地窖镜头要求“只闻其声”，结果怪物直接露头。
   - 规则：需要保持不可见时，显式写否定约束，例如 “no creature bodies, faces, claws, or silhouettes visible”。（WWHD）

## 提示词服务

4. **shot-video-prompt 接口偶发超时**
   - 症状：自动单镜提示词接口超时，后续视频任务连带失败。
   - 原因：本地 11434 视觉模型在并发下不稳定。
   - 规则：提示词生成串行执行；超时一次立即重试，二次失败改手工组装视频提示词并在状态表标注“手工提示词”。（WWHD）

## MiniMax / 视频

5. **对白重复描述会增加台词跑偏风险**
   - 症状：生成视频中的台词不正确，或同一台词出现重复/竞争性描述。
   - 原因：MiniMax H3 把对白和其他音画指令一起通过单一 prompt 条件化；重复出现的原句会形成竞争性文本条件（基于 `FWW_0010` 对照测试的经验判断）。
   - 编写规则统一见 `prompts_structure/shot/minimax.md` 与 `prompts_structure/sequence/minimax.md`，避免在执行层另存一份提示词规范。`FWW_0010` v003 对照版台词正确；该写法提高可控性但不保证每次生成都准确。高准确度需求仍需标记后期配音。（复生协议 ACT2 / FWW_0010 v003）

6. **背景元素运动幅度失控**
   - 症状：静态背景物体自行运动，或微风下大型设施转动过快。
   - 规则：把本镜需要的运动与需要保持稳定的可见锚点写清；微动尽量给可观察的上限（如“5秒内转角不超过约3°”）。不要为尚未出现的问题预先罗列排除项。（复生协议 ACT2 / FWW_0010 v003）

7. **Storyboard 裁切图被直接用作视频关键帧**
   - 症状：MiniMax 视频整体发糊，人物和环境的细节分辨率不足。
   - 原因：从 storyboard/contact sheet 裁出的单格只有 545×307，却被当作 1344×768 视频的首帧参考；小图无法提供足够的细节信息。
   - 规则：为视频单独生成完整、清晰的 16:9 镜头关键帧；不要将 storyboard 格子裁图直接作为最终关键帧，也不要依靠视频模型放大。关键帧至少 1536×864，优先 1920×1080 或渲染器支持的更高原生 16:9 尺寸，并在提交前检查像素尺寸不低于视频输出尺寸。（复生协议 ACT2 / FWW_0010）

8. **负面修正应由实际生成问题触发**
   - 规则：提示词先描述目标画面，不预先罗列不存在或未发生的问题。只有生成结果出现具体问题（如意外切镜、重复人物或某种异常运动）时，才加简短、定点的修正约束；若 MiniMax 接口只有一个 `prompt` 字段，这类文字不是独立负面条件。单次结果只能支持局部经验，不要把它泛化为“负面词必然触发目标物”。（复生协议 ACT2 / FWW_0030、FWW_0090）
   - 连续全景个案：FWW_0090 v011 出现人物特写切镜；v012 在同一工作流和参考图下，将动作合并为少数阶段、反复锁定广角构图，并只针对已出现的切镜加短修正后，抽查时间点均保持全景，但仍有轻微前移和人物踩上池沿。该对照支持先简化动作并强化构图锚点的做法，不能单独证明其中某一项必然有效。（复生协议 ACT2 / FWW_0090 v011→v012）

10. **水景中的异常形态：保留单镜头经验，不作通用禁令**
   - FWW_0090 对照中，移除水相关负面词的 v010 抽查未见额外喷柱，但人物动作较早停下；带水相关负面词的版本曾出现喷柱。它提示我们不要提前为水景罗列异常形态；只有实际出现后，才针对该镜测试简短修正，同时检查动作和镜头连续性。该结果是单镜头经验，不代表负面词普遍会诱发被点名对象。（复生协议 ACT2 / FWW_0090 v005→v010）

9. **MiniMax 把特效过程板当成镜头画面，或忽略过程阶段**
   - 症状：含分格过程板的参考图可能诱导 MiniMax 直接生成分格/版式；如果只笼统说“按过程图变化”，模型也可能跳过中间阶段或改错运动方向。
   - 规则：关键帧始终锁定整幅视频画面；entity 最完整概念图锁定设计，另提供与本镜头状态相符的单体参考图；复杂特效过程板只作为该 entity 的运动与阶段参考。提示词明确列出每格对应的秒数、可见形态和运动方向，并明确过程板不提供视频构图、场景或版式。FWW_0040B v007 将第2格写成“左侧菱形向右输送粒子、右侧形成 panel”后，抽帧比 v006 更接近过程图：1.5 秒仍同时看见左侧菱形和右侧 panel，2.7 秒接近第3格，4.2 秒接近完成态。按镜头抽帧比较这些映射，但不把单次生成视为严格遵循或保证。（复生协议 ACT2 / FWW_0040B v006→v007）

10. **故事板与概念参考互相强化了错误造型**
   - 症状：ACT2_0100 v007/v009 的巨型水精灵出现多处石块；故事板里的喷泉雕塑也与获批镜头中的雕塑形状有偏差。
   - 原因：v009 实际上传的是 camera-growth storyboard v001（巨型形态画有多块石头），同时完整水精灵概念图和背面单体图也都包含悬浮/嵌入的暗色石块；v008 使用的 camera-growth storyboard v002 同样未完全去除这些块。明确写“参考职责”不能抵消图像本身反复呈现的设计。角色参考仍被接入并保留了大致身份/服装，但不是像素细节注入。v009 的运镜故事板为彩色高细节图，不能可靠地只传递机位。
   - 规则：先检查最终将提交的每张参考图是否都符合目标；若要“纯水+唯一中央芯片”，需同时换成无石块的实体设计图、背面图及过程/运镜图，不能只改提示词。布局图优先用简洁黑白线稿，仅表达画面安排和运动；雕塑等固定场景造型以获批关键帧/场景概念图为唯一权威，逐格核对轮廓。概念图补身份与造型，但不提高视频像素分辨率或保证细节逐项复制。以上是 ACT2_0100 的个案经验，下一次应通过单变量对照验证。（复生协议 ACT2_0100 v007→v009）

## 环境

7. **ComfyUI 端口漂移**
   - 症状：后端报 `comfyui_connected=false`。
   - 原因：机器上存在多套 ComfyUI（8000 / 8188），启动入口不唯一。
   - 规则：开工前先确认后端 status 里 `comfyui_connected=true` 再批量提交。（WWHD）
11. **冲刺动作需量化时间窗与位移；缩短时长可作单变量对照**
   - 症状：FWW_0120B v001 的3秒提示词虽写了“rapidly / several powerful strides / natural running speed”，回放仍显得偏慢。
   - 对照：v002 沿用同一组5张参考图、int8纯多参工作流、画幅和机位，只把请求时长从3秒降到2秒，并明确前1.5秒推进约两个身位、第一帧已经全速跑、结尾仍处于冲刺。输出实际为2.333秒；抽帧显示动作更紧凑、横向推进更明显，但是否达到用户期望的速度感仍需回放确认。
   - 规则：动作偏慢时，先保持参考图和场景条件不变，明确动作发生的时间窗与可观察位移/循环次数；再单独缩短请求时长作对照。输出时长可能按帧率取整，且单次测试不保证模型速度会线性变化。镜头时长仍须容纳剧情动作。
   （复生协议 FWW_0120B v001→v002）
