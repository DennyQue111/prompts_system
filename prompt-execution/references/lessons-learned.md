# 制作问题归档

按“症状 → 原因 → 规则”记录。新问题追加到对应分类，不要删除旧条目。来源项目标注在条目末尾。

## Flux / 关键帧

1. **多视图 concept sheet 被当成多人物**
   - 症状：用三视图 character sheet 做关键帧参考，画面里出现两个人。
   - 原因：Flux 会把同一个人的多视图误读为多个角色。
   - 规则：concept sheet 只做设定确认；关键帧与视频参考改用单角色身份锚图。多角色镜头 = 每个角色一张身份锚图 + 一张构图锚图。（WWHD）

2. **抽象氛围被实体化**
   - 症状：“黑暗中的诡秘嬉笑”生成背景里两张女人脸。
   - 原因：Flux 会把抽象描述具象成实际实体。
   - 规则：Flux 提示词只写可见证据；抽象气氛拆成光、雾、声源方向等具体画面元素。（WWHD）

3. **“不可见的危险”被画出来**
   - 症状：地窖镜头要求“只闻其声”，结果怪物直接露头。
   - 规则：需要保持不可见时，显式写否定约束，例如 “no creature bodies, faces, claws, or silhouettes visible”。（WWHD）

## 提示词服务

4. **shot-video-prompt 接口偶发超时**
   - 症状：自动单镜提示词接口超时，后续视频任务连带失败。
   - 原因：本地 11434 视觉模型在并发下不稳定。
   - 规则：提示词生成串行执行；超时一次立即重试，二次失败改手工组装视频提示词并在状态表标注“手工提示词”。（WWHD）

## MiniMax / 视频

5. **对白重复描述会增加台词跑偏风险**
   - 症状：生成视频中的台词不正确，或同一台词出现重复/竞争性描述。
   - 原因：MiniMax H3 的原生音视频流程没有独立对白字段；对白与其他音画指令一起通过 prompt 条件化。重复写台词可能造成相互干扰（此处为基于单镜对照测试的经验判断）。
   - 规则：原句只在独立的“对白”段落出现一次，明确说话者、时间窗、语气和口型同步；动作段用“说出本镜唯一一句台词”指代，不再复述原句，声音设计段也不重复台词。`FWW_0010` v003 按此格式后台词正确；这能提高可控性，但不保证每次生成都完全准确。台词对成片准确度要求很高时，仍标注“需后期配音”。（复生协议 ACT2 / FWW_0010 v003）

6. **背景元素运动幅度失控**
   - 症状：静态背景物体自行运动，或微风下大型设施转动过快。
   - 规则：把持续运动、保持静止和微动对象分别写清；对微动尽量给可观察的上限（如“5秒内转角不超过约3°”），对不应出现的对象明确写“全程空置/不出现”。只写“慢一点”不够精确。（复生协议 ACT2 / FWW_0010 v003）

7. **Storyboard 裁切图被直接用作视频关键帧**
   - 症状：MiniMax 视频整体发糊，人物和环境的细节分辨率不足。
   - 原因：从 storyboard/contact sheet 裁出的单格只有 545×307，却被当作 1344×768 视频的首帧参考；小图无法提供足够的细节信息。
   - 规则：为视频单独生成完整、清晰的 16:9 镜头关键帧；不要将 storyboard 格子裁图直接作为最终关键帧，也不要依靠视频模型放大。关键帧至少 1536×864，优先 1920×1080 或渲染器支持的更高原生 16:9 尺寸，并在提交前检查像素尺寸不低于视频输出尺寸。（复生协议 ACT2 / FWW_0010）

## 环境

7. **ComfyUI 端口漂移**
   - 症状：后端报 `comfyui_connected=false`。
   - 原因：机器上存在多套 ComfyUI（8000 / 8188），启动入口不唯一。
   - 规则：开工前先确认后端 status 里 `comfyui_connected=true` 再批量提交。（WWHD）
