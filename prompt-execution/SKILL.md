# Prompt Execution

本 skill 定义与视频模型无关的生产流程：**先做什么、何时确认、如何检查、失败后怎么处理、经验记到哪里**。

- `prompts_structure` 定义各视频模型的提示词组织、动作/镜头写法、对白与负面约束写法。执行时按镜头类型和模型选择对应模板；本 skill 不复制模板正文或提示词段落规范。
- 本 skill 的模型适配说明只记录生产执行差异，例如参考图/首尾帧的绑定能力、任务提交字段、输出位置、状态查询与轮询方式。
- 图像资产、应用接口或特定项目的额外步骤由 `references/` 下的专题说明提供。
- 现有视频提示词结构：连续单镜路由到 `prompts_structure/shot/<model>.md`；含剪辑的 sequence 路由到 `prompts_structure/sequence/<model>.md`。MiniMax 和 Seedance 的提示词差异只维护在各自模板里。

当用户要求复盘已有镜头或初剪，先按 [editing-review/SKILL.md](../editing-review/SKILL.md) 检查成片并形成修改清单；新增或重做镜头再回到本流程。

## 生产流程

按阶段推进并记录。具体镜头可以跳过不需要的视觉资产阶段，但不得跳过确认门或质量检查。

1. **定义风格与生产工具**：确认项目风格、图像生成器、视频模型和目标应用。用少量代表画面确认风格；用户确认前不批量生产概念图或镜头锚点。已确认风格保持一致，除非用户要求更改。
2. **准备概念资产**：按图像生成器专属流程制作角色、场景、entity 和重要道具概念资产。检查资产并保存来源与路径。图像生成器差异见 [references/pipeline.md](references/pipeline.md) 及对应应用集成文档；视频模型需要哪种概念图、参考图数量与用途，查所选视频模型适配说明。
3. **拆分镜头**：按 [shot-planning/SKILL.md](../shot-planning/SKILL.md) 将剧本大纲或场次整理为 `concepts + shot_breakdown`。填写镜头意图、时长、动作、景别/运镜、连续性及必要的声音信息。
4. **确认镜头表**：将完整镜头表交给用户确认。确认前不生成关键帧、整镜故事板或视频。确认后记录结论，后续变更只更新受影响部分。
5. **选择视觉锚点路线**：逐镜选择关键帧路线或故事板路线；关键帧不是每镜必需。
   - **关键帧路线**：适用于需要精确首帧、构图或已确认画面的镜头。根据图像生成器制作与本镜机位匹配的完整关键帧，并检查身份、动作、构图、空间、尺度、左右侧别和环境状态。
   - **故事板路线**：适用于复杂连续运镜、多个全彩关键帧构图互相冲突、或关键帧易使连续镜头看起来像剪辑片段的情况。整镜/sequence 故事板负责布局、景别、动作阶段和摄影机路径；角色/entity/道具概念图负责主体设计；一张一致的场景概念图负责环境外观、色调和光线。不必为满足流程强行补彩色关键帧。
6. **制作与检查故事板**：无论单镜头、sequence、多镜头还是特效状态故事板，均须逐格生成独立图片，逐格检查内容与前后衔接后，再用本地确定性图像处理合并。禁止要求 GPT 或其他生图模型一次性直出整张多格故事板。保留单格原图与合成图；拼版不拉伸、不重绘、不改格内内容。每格统一画幅比例与明确阅读顺序。默认使用清晰、高对比度的黑色线稿，轮廓、朝向、手势和特效动作一眼可辨，细节从简；不使用过淡、发灰或松散到无法辨认动作的线条，不使用彩色或灰阶填充。格数由关键动作、运镜和特效阶段决定，不设固定数量；重要特效须展示其出现、运动方向、交互或结果。
7. **视觉锚点确认与回填**：逐格核对主体数量、姿态、动作方向、画面关系、镜头景别、摄影机路径、地平线和固定地标。检查概念图与前后镜连续性、光照及环境后果。若输入参考间有冲突，先明确各自职责并修正素材。用户确认的关键帧/故事板通过后，将实际采用的路径及图片职责回填镜头表；概念图路径回填 `concepts`。记录路线为 `keyframe-led` 或 `storyboard-led`。
8. **选择视频模型并准备执行**：先读取对应的 `prompts_structure` 模板，再读取该模型的执行适配说明。提示词段落、动作表达、对白与负面约束遵循 Prompt Structure，不在 Execution 另写一遍。模型适配说明仅补充实际执行差异。若模型没有执行适配说明，先核实目标应用/服务的真实能力，不从其他模型推断接口或工作流。
   - 参考素材按执行适配说明绑定。storyboard-led 的通用顺序为：**合并后的整镜/sequence 故事板在前，所需角色/entity/道具概念图随后，唯一场景概念图最后**；若某模型明确不支持这一顺序或使用不同输入字段，适配说明中记录机械绑定方法，但不能改变素材职责。`@图片N` 或等价标签必须与实际输入顺序/字段一致。
   - keyframe-led 的图像顺序按关键帧/开场画面在前、设计概念素材随后；特定模型的首帧/首尾帧锁定方式以适配说明为准。
9. **提交、监控与质检**：提交前确认服务与渲染后端可用；保存准确的请求参数、提示词、参考图顺序、任务 ID 和提交时间。按模型适配说明轮询任务，不以接口暂时无响应推断任务失败。完成后确认输出文件存在、格式/时长/尺寸正确，并实际观看检查动作、运镜、连续性、环境和声音；通过后回填视频路径和状态。
10. **复盘**：一轮制作结束后核对所有镜头状态，将新发现的问题追加到 [references/lessons-learned.md](references/lessons-learned.md)。单次结果只能形成有范围的经验，不把个案写成模型必然规律。

## 状态跟踪

为每个镜头维护可追溯状态：

`pending → style_confirmed → anchors_ready → breakdown_confirmed → (keyframe_ready | storyboard_ready) → video_submitted → video_done`

异常态使用 `blocked(原因)`。保存请求 ID、已确认资产路径、提示词/模板版本和失败原因。任何镜头不得静默跳过；失败需记录并安排回补。

## 通用失败处理

遵守 [references/retry-policy.md](references/retry-policy.md)。系统性故障排除前不继续提交；内容跑偏时改对应素材或约束后有限重试；达到重试上限后记录 blocked，不把未通过质检的视觉锚点送入视频阶段。

## 执行纪律

- 时长、尺寸、参考图数量、帧率和锁帧方式均依目标视频模型/应用的已核实限制与用户要求，不设置跨模型的固定默认值。
- 生成提示词或图像的本地辅助服务串行调用；渲染任务按设备能力排程，防止无控制并发。
- 开工先核实所选应用和渲染后端状态；若不可用，保留计划与素材并报告，不提交任务。
- 不把单镜生成接口称为完整自动化编排器。若应用没有批量编排能力，应逐镜提交、检查并回填状态。
- 新素材及输出路径遵循目标应用和项目当前约定；写入 JSON 前确认文件存在、URL 可访问。
