## Description

即梦（Jimeng）平台的故事板提示词结构。与 Gemini/GPT 不同，即梦使用**中文模块化提示词**，参考图通过**相似度滑块**控制，且有 **2000 字符限制**——故事板多帧描述需要更精炼的表达。

**Base architecture + scene-type specializations** → see `gemini.md`。本文件为**即梦专用覆盖层**。先加载 `gemini.md` 获取完整故事板架构（布局网格、摄影叙事、场景类型特化、通用关键规则），再用本文件做即梦适配。

本文件覆盖即梦与 Gemini/GPT 的关键差异：
1. 中文模块化提示词（vs 英文长句）
2. 2000 字符限制下的帧数与取舍策略
3. 相似度滑块参考图控制（vs 纯文字声明）
4. 黑白线稿风格在即梦中的锚定方法

---

## 即梦故事板工作流

1. **上传参考图**（1–2张）
   - 角色概念图：**角色特征**模式，中高相似度（60–75%），锁定角色设计但不复制色彩
   - 场景概念图：**风格参考**模式，低相似度（30–40%），提取环境空间感但不复制色彩
   - ⚠️ 参考图通常是彩色的，但故事板是黑白线稿——必须在【风格锚定】中明确声明"纯黑白线稿，无色彩"

2. **写中文提示词**（结构见下方）
   - ⚠️ **字数限制：即梦 prompt 输入框有 2000 字上限。** 故事板多帧描述信息量大，必须按优先级取舍（见下方取舍原则）。

3. **调整反向提示词**（中文，5–8 个词）

4. **选择画风标签**：「动漫」或「插画」+ 在 prompt 内重复声明黑白线稿风格

## 提示词结构（中文）

```
@image [文件名.扩展名] — [参考图类型：角色特征锁定/风格参考]：[具体说明要还原什么、不复制什么]。
（如有多张参考图，每张单独一行 @image 声明）

【Layout 布局】
16:9 故事板，[N×M] 网格，[N] 帧，细黑色边框，纯白背景。帧标签为小号清晰文字。从左到右、从上到下阅读。

【场景背景】
[场景编号，地点，时间，情绪弧线一句话概括]

【角色锚定】
"[角色名]，[年龄]，[体型]，[发型]，[服装]，[标志性特征]。所有帧角色设计一致。"

【分镜描述】
第1帧（[景别]—[节拍]）：[人物] + [动作/瞬间] + [关键视觉细节]。镜头：[焦距]，[角度]，[运镜]。光线：[光源方向，阴影质感]。
第2帧（[景别]—[节拍]）：[人物] + [动作/瞬间] + [关键视觉细节]。镜头：[焦距]，[角度]，[运镜]。光线：[光源方向，阴影质感]。
...
第N帧（[景别]—[节拍]）：[人物] + [动作/瞬间] + [关键视觉细节]。镜头：[焦距]，[角度]，[运镜]。光线：[光源方向，阴影质感]。

【风格锚定】
纯黑白线稿，清晰墨线风格，漫画故事板版面，无灰度填充——纯高对比线稿，无任何色彩，纯白背景，专业电影分镜，所有帧角色设计一致

【反向提示词】
文字，水印，色彩，3D渲染，多余人物，照片质感
```

### 帧微格式

每帧 2–3 句中文，描述画面可见内容。不写内心活动、情绪解读、叙事意义。

```
第N帧（[景别]—[节拍名]）：
[主体] + [动作/瞬间—仅视觉证据] + [关键视觉细节]。
镜头：[焦距mm]，[角度]，[运镜]。光线：[光源方向，阴影质感]。
```

- 景别：全景 / 中景 / 近景 / 特写 / 大特写
- 角度：平视 / 仰拍 / 俯拍 / 荷兰角
- 运镜：固定 / 缓推 / 横摇 / 手持跟拍 / 升降
- 节拍参考 `gemini.md` → Story Beat Pattern：建立→行动→反应→转折

## 帧数与视频时长

| 视频时长 | 帧数 | 网格布局 | 说明 |
|---------|------|---------|------|
| 5s | 3–4 帧 | 3×1 或 2×2 | 最小：建立→行动→反应 |
| 10s | 5–6 帧 | 3×2 | 标准：完整四拍弧线 |
| 15s | 6 帧 | 3×2 | 即梦推荐上限——更多帧易超字数 |
| 20s+ | 不推荐 | — | 字数限制下帧描述过于精简，建议拆分多张故事板 |

**即梦默认 6 帧（3×2，10s 基准）。** 超过 6 帧时帧描述被迫压缩，角色一致性风险急剧上升。长场景拆分为多张故事板分别生成。

## 与 Gemini/GPT 故事板的关键差异

| 维度 | Gemini/GPT | 即梦 |
|------|-----------|------|
| 语言 | 英文长句复合描述 | 中文短句模块化 |
| 参考图控制 | 纯文字声明 boundaries | 相似度滑块 + 文字声明 |
| 字数限制 | 无明确限制（GPT 可写很长） | 2000 字硬上限 |
| 帧数上限 | 8–12 帧可行 | 6 帧推荐上限 |
| 风格锚定 | 长段英文风格后缀 | 中文关键词 + 画风标签 |
| 反向提示词 | 英文 Avoid 列表 | 中文排除词，逗号分隔 |
| 角色一致性 | 文字描述锚定（易漂移） | 角色特征模式 + 相似度滑块（视觉锚定更强） |
| 布局生成 | 英文 layout instruction | 中文【Layout 布局】模块 |
| B&W 锚定 | style suffix 一句搞定 | 需在风格锚定 + 反向提示词 + 画风标签三重锚定 |

## 黑白线稿三重锚定

即梦默认生成彩色图像，黑白线稿需要三重锚定才能稳定：

1. **【风格锚定】中明确声明**：`纯黑白线稿，清晰墨线风格，无灰度填充，无任何色彩，纯白背景`
2. **【反向提示词】中加入**：`色彩，彩色，3D渲染，照片质感`
3. **画风标签选择**：`动漫` 或 `插画`（不要选`写实`或`摄影`）

如果生成结果仍然带色，在【风格锚定】末尾追加：`绝对无色彩，仅黑色线条和白色背景，禁止任何颜色`。

## 参考图声明

即梦的 `@image` 声明用于项目内部规范，即梦平台不读取文件名，但上传时需手动选择参考模式。

**角色概念图（角色特征模式）：**
```
@image XiaoWu_concept.png — 角色特征锁定：还原面部、发型、体型、服装、机械臂细节。不复制背景、构图、色彩。仅作角色设计参考，故事板为黑白线稿。
```

**场景概念图（风格参考模式）：**
```
@image location_concept.png — 风格参考：提取环境空间感、建筑特征、光源方向。不复制具体色彩、不复制图中人物。仅作场景环境参考。
```

⚠️ **务必在每张参考图声明中加入"故事板为黑白线稿"**——防止即梦从彩色参考图中带入色彩。

## 字数超限时的取舍原则

若 prompt 接近 2000 字上限，按以下优先级删减：

| 优先级 | 内容 | 说明 |
|--------|------|------|
| 绝对保留 | 【Layout 布局】 | 没有布局声明，即梦不知道生成多面板 |
| 绝对保留 | 【角色锚定】 | 角色一致性是 #1 问题 |
| 绝对保留 | 【风格锚定】 | 黑白线稿必须三重锚定 |
| 绝对保留 | 每帧的：景别 + 动作 + 焦距 | 核心分镜信息 |
| P1 尽量保留 | 每帧的：运镜 + 光线 | 帮助理解镜头语言 |
| P2 可精简 | 每帧的：关键视觉细节 | 压缩为半句 |
| P3 可删除 | 每帧的：光线描述 | 折入【场景背景】一句概括 |
| P3 可删除 | 【场景背景】的细节 | 压缩为"地点+时间"四个字 |
| P4 可删除 | 【反向提示词】 | 如果三重锚定已生效，可省略 |

**精简技巧：**
- 帧描述用顿号分隔关键词，不用完整句子："小武背影，走入巷道，右臂藏口袋。镜头：35mm，低位跟拍。"
- 多帧共享的环境描述（光源、建筑）提取到【场景背景】，帧内不重复
- 运镜和角度合并："低位手持跟拍"而非"低位+手持+跟拍"

## 反向提示词写法

**宜短不宜长，5–8 个词。** 正面锚定已排除的，反向不再重复。

故事板专用反向：
```
文字，水印，色彩，3D渲染，多余人物，照片质感
```

- **色彩**：故事板是黑白线稿，这是最重要的反向项
- **文字**：即梦容易在画面中生成乱码文字
- **多余人物**：防止即梦从参考图中带入不相关的人物
- 如果生成结果没有这些问题，可以**完全不用反向提示词**，把字数留给帧描述

## 即梦关键规则

1. **中文优先**：即梦对中文短句模块化描述理解最精准。英文风格关键词可保留在【风格锚定】中。
2. **6 帧上限**：即梦 2000 字限制下，6 帧（3×2）是最佳平衡点。更多帧会导致帧描述过于精简，角色一致性风险急剧上升。
3. **黑白线稿三重锚定**：即梦默认生成彩色——必须在【风格锚定】+【反向提示词】+ 画风标签三处同时声明黑白线稿。
4. **相似度不等于一切**：即使角色特征模式高相似度，也要用文字声明"不复制背景/构图/色彩"，否则即梦容易把参考图的整体风格一起带过来。
5. **参考图声明必须注明黑白**：`@image` 声明中加入"故事板为黑白线稿"，防止从彩色参考图带入色彩。
6. **角色一致性是即梦的优势**：相比 Gemini/GPT 纯文字锚定，即梦的角色特征模式 + 相似度滑块对角色一致性的控制更强——但要控制相似度不要太高（60–75%），否则即梦会复制参考图的构图和背景。
7. **Layout 先于内容**：开篇先声明【Layout 布局】的网格结构，再逐帧描述内容。即梦对布局声明的遵循度不如 Gemini/GPT，需要简洁明确。
8. **场景类型特化**（action/dialogue/vfx/mixed）：规则见 `gemini.md` → Scene-Type Specializations，按帧应用。即梦的中文描述需对应翻译核心概念。
9. **No dialogue text on panels**：不在故事板面板上写对白文字。对白通过角色表情、肢体语言、唇形传达。面板文字仅限于帧标签和 2–3 字动作注释。见 `gemini.md` → Key Rule 11。
10. **字数超限时先减帧数**：如果 6 帧的描述无法在 2000 字内写完，减到 4 帧（2×2），而不是压缩每帧描述到不可读。
