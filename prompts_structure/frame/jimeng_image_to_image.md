## Description

即梦（Jimeng）平台的 image-to-image 提示词结构。与 GPT/Gemini/Midjourney 不同，即梦对中文语义理解更直接，参考图功能以「相似度滑块」控制，提示词需要更明确地划分「参考图锁定范围」和「新生成内容」。

**适用场景：** 上传角色概念图或风格参考图，在即梦生成同风格/同角色的新图。

**前置必读：** 撰写任何 prompt 前，请先阅读 [`meta/prompt-hygiene.md`](meta/prompt-hygiene.md) 中的八条横切规则与四问自检清单。

---

## 即梦 i2i 核心工作流

1. **上传参考图**（1–3张）
2. **选择参考模式**
   - **角色特征**：高相似度（75–90%），严格锁定面部/发型/体型
   - **风格参考**：中低相似度（30–50%），提取色调/笔触/氛围
   - **构图参考**：中相似度（50–65%），锁定空间关系
   - ⚠️ **风格锁定优先**：i2i 默认直接继承参考图 style（画风/笔触/渲染质感/配色）。确定按图走 → @image 行一并锁定 style + 删【风格锚定】；不确定是否按图 style 走 → 先跟用户确认再落 prompt。
3. **写中文提示词**（结构见下方）
   - ⚠️ **字数限制：即梦 prompt 输入框有 2000 字上限。** 优先保证【画面主体】【镜头与构图】【风格锚定】三项，其他模块按需取舍。
4. **调整反向提示词**（中文，5–8 个词）
5. **选择画风标签**（如「动漫」「插画」「概念设计」）辅助锚定

## 提示词结构（中文）

```
@image [文件名.扩展名] — [参考图类型：角色身份锁定/风格DNA提取/构图参考]：[具体说明要还原什么、不复制什么]。角色/风格锁定模式下，本行一并锁定该图整体风格，后续【风格锚定】默认删除。
（如有多张参考图，每张单独一行 @image 声明）

【画面主体】
[人物] + [动作/姿态] + [表情情绪] + [服装细节]

【镜头与构图】
[景别：特写/中景/全景] + [角度：平视/仰拍/俯拍] + [构图描述]

【风格锚定 — 可选，默认删除】
⚠️ 默认不写。若已通过 @image 锁定参考图风格，本段整段删除——重复声明风格反而污染画面（风格锚定就是污染提示词）。
仅当未确定按参考图风格走、或需要额外风格约束时，才写：[直接引用项目 style_profile.md 的核心中文描述，或即梦风格标签]

【环境氛围】
[背景] + [光源方向与硬度] + [主导色调] + [天气/空气感]

【环境动态 — 可选但强烈建议】
[风/气流方向与强度] + [受影响元素：头发飘动、草摆动、布料褶皱、尘埃/粒子] + [动态带来的画面层次]

【质感说明 — 可选，参考图已锁定时可删】
[关键材质：皮肤/布料/金属/地面等。若参考图已精确描述服装/地面材质，此模块可省略。]
```

**@image 格式说明：**
- 在即梦平台上，参考图通过上传功能绑定，prompt 内的 `@image 文件名` 用于**明确声明该图的用途边界**（即梦不读取文件名，但这是项目内部的规范写法，便于维护和多平台迁移）。
- 单张角色参考：`@image xiaowu_base.png — 角色身份锁定：精确还原面部、发型、体型。不复制背景、构图、表情。`
- 单张风格参考：`@image location_ref.png — 风格DNA提取：提取色调、笔触、氛围。不复制具体建筑。`
- 多张参考时每张单独一行声明，避免混淆。

## 与 GPT/Gemini 提示词的关键差异

| 维度 | GPT/Gemini | 即梦 |
|------|-----------|------|
| 语言 | 英文为主，长句复合描述 | 中文为主，短句模块化 |
| 参考图控制 | 纯文字声明 boundaries | 相似度滑块 + 文字声明 |
| 风格锚定 | 长段自然语言风格后缀 | 风格标签 + 短句关键词 |
| 反向提示词 | 英文 Avoid 列表 | 中文排除词，逗号分隔 |
| 负面长度 | 可较长（15–25词） | 宜短（10–15词），过长易失效 |
| 特殊能力 | 强语义理解，可推复杂光影 | 强视觉参考跟随，需明确光源方向 |

## 即梦风格标签建议

⚠️ 仅在**未通过 @image 锁定参考图风格**（即需要额外风格约束或换风格）时才在 prompt 内写风格。已锁风格时，勾选预设标签即可，无需在文字重复。

生成时勾选或Prompt内明确：
- **大类**：`动漫` / `插画` / `概念设计` / `二次元`
- **细化**：`厚涂` / `赛璐璐` / `手绘风` / `电影感`
- **本项目推荐**：在提示词内写 ` polished 2D anime key visual, 手绘质感，完成度高，2D平面，数字绘画完成品`

## 反向提示词写法（中文）

**宜短不宜长，5–8 个词最佳。** 即梦的反向提示词过长时后半截会失效，且容易与正面描述产生冗余对冲。

**核心原则：正面锚定已排除的，反向不再重复。**

| 正面已声明 | 反向无需再写 |
|-----------|-------------|
| @image 已锁参考图风格（未另写风格锚定） | 反向不要再写风格类排除词（3D渲染/真实皮肤/矢量扁平） |
| 风格锚定（换风格时）写了"非3D渲染、非真实感、非矢量扁平" | 反向不要再写"3D渲染、真实皮肤、矢量扁平" |
| 风格锚定（换风格时）写了"绝非草图、完成度高" | 反向不要再写"草图、未完成" |
| 质感说明写了"无真实毛孔" | 反向不要再写"真实皮肤" |

反向只保留**正面无法覆盖、且反复错误出现的具体元素**：

```
文字，水印，多余人，游乐园建筑，多云，阴天，缺少黑色立方体
```

如果生成结果没有这些问题，甚至可以**完全不用反向提示词**。

## 环境动态设计原理

静态的画面容易显得死板。加入环境动态不是为了增加复杂度，而是让画面获得三个层面的提升：

1. **时间感**：风、飘动的草、飞扬的尘土让一帧静止图有了"前一秒"和"下一秒"的暗示，观者会自然地感受到这是一个活着的、正在呼吸的世界。
2. **连接感**：人物头发的飘动与地面草簇的摆动共享同一股风，这种"共享运动"把角色和环境从视觉上缝合在一起，消除人物像贴图一样浮在背景上的感觉。
3. **空气层次**：阳光中漂浮的微尘或地面卷起的细沙，在前景与中景之间形成天然的半透明隔离层，增强画面的空间纵深感。

**设计方法**：先问"这个环境里空气在怎么流动？"——沙漠戈壁有持续的干燥热风；雨夜有湿冷的垂直下落；废弃建筑内有停滞的闷热。然后让风至少影响两个可见元素（头发 + 草，或布料 + 尘埃），画面立刻丰富起来。

## 关键规则

1. **中文优先**：即梦对英文长句的理解不如中文短句精准。
2. **模块化**：用【】或换行把参考图锁定、主体、风格、环境分开，降低模型混淆。
3. **相似度不等于一切**：高相似度下也要用文字声明「不要复制背景/构图」，否则即梦容易把参考图的整体构图一起带过来。
4. **风格锁定优先于风格描述**：i2i 直接继承参考图 style，@image 行锁定 style 后，不再写【风格锚定】段——重复声明风格反而污染画面（风格锚定就是污染提示词）。即梦「动漫」「插画」预设标签仍可勾选辅助。
5. **材质词汇统一**：所有图使用同一套材质词（见项目 `style_profile.md` 材质词汇表），防止帧与帧漂移。
6. **环境动态不可忽视**：即梦对"风吹头发""草摆动""沙尘"这类中文描述的理解很直接，写入【环境动态】模块能显著提升画面生动感。
7. **字数超限时的取舍原则**：若 prompt 接近 2000 字上限，按以下优先级删减：
   - 第一删：【质感说明】（参考图已精确锁定服装/地面材质时）
   - 第二删：【环境动态】中的细节修辞，保留风+受影响元素的核心句
   - 第三删：【环境氛围】中的情绪形容词，保留背景+光源+色调的骨架
   - 绝对保留：【画面主体】【镜头与构图】；【风格锚定】默认删除
8. **风格意图先确认**：不确定是否按参考图 style 走时，先跟用户确认再写。确认「按图 style 走」→ @image 锁定 style + 删【风格锚定】；确认「换风格」→ 才写【风格锚定】。
